# Demo Goal And Planning Guide

Create a short storyboard that connects the project purpose to a visible, reproducible flow.

## Planning Inputs

- Project understanding summary.
- User-provided demo goal, if available.
- Inferred default demo goal, if the user did not provide one.
- Known setup and runtime constraints.
- Available capture tools.

## Goal Clarification

If the user provides a demo goal, preserve it and make it operational. If the user does not provide one, infer a default goal from the project purpose, primary user journey, and features that can be verified in the current environment.

## Storyboard Requirements

The demo plan should include:

- Opening state.
- Setup or preconditions.
- Key interaction steps.
- Expected result for each important step.
- Final screen or outcome.
- Evidence to capture.
- Risks and fallback paths.

## Human Viewer Check

Before executing the demo, check whether a viewer would understand:

- What the project is.
- Why the demonstrated flow matters.
- What changed during the demo.
- What success looks like.
- What limitations remain.

## Default Planning Heuristics

- Prefer one clear story over many shallow feature flashes.
- Start from a recognizable state.
- Show user intent before showing output.
- Keep setup steps reproducible but not visually dominant.
- Use realistic sample data when possible.
- Avoid hidden state that future viewers cannot recreate.
